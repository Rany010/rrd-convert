# rrd-convert · 产品定义

记录日期：2026-10-30。

副标题：go from any bag to Rerun — 多格式适配进 `.rrd`：快、简单、可扩展，开箱就能看见效果。

## 一句话定位

rrd-convert 给智能驾驶和机器人工具链做离线转换。一条命令把存量记录变成可打开的可视化结果。输入格式可插拔，v1 先支持标准 ROS 2 `.db3`。可视化引擎也可插拔，v1 先写 Rerun `.rrd`。标准消息开箱可用，自定义消息和自定义引擎都通过注册接入。

## 产品原则

1. 快而简单，多格式兼容
   - 默认路径：安装 → 一条命令 → `rerun out.rrd`
   - 输入走 Format Adapter。v1 实现标准 ROS 2 `.db3`，接口预留 `.bag`、MCAP 和其它存储
2. 两端都能二次开发
   - 前面用输入中间表示收齐各种存储
   - 后面用可视化中间表示接各种引擎
   - 解码按消息类型注册，不在主循环里按话题名分支
   - 自研或厂商消息、Foxglove、socket 流、自定义格式都以插件或独立包接入
   - 文档带最小插件示例
3. 容易快速看到效果
   - 样例 bag 使用仓库内生成的合成 `.db3`
   - 内置常见 `sensor_msgs`、`tf2_msgs`、`visualization_msgs`
   - 成功标准：新人 10 分钟内在 Rerun 里看到画面
   - 简易默认 blueprint 放在第一条转换跑通之后，仍属于 v1，不挡住第一条路径

## 目标用户与场景

| 项 | 范围 |
|----|------|
| 主用户 | 智驾 / 机器人工具链、评测、调试；有存量 bag，想快速进 Rerun |
| 核心场景 | 离线转换标准 ROS 2 `.db3`，免完整 ROS 工作区也能看传感器数据 |
| 扩展场景 | 插件接入自研或厂商消息；CI 批量转换；日后更换存储或可视化引擎 |
| 非场景 | 完整业务可视化套件、仿真器、回灌评测引擎、实车上回放控制 |

## 用户旅程

1. 安装。单包安装，不要求完整 ROS 2 发行版。
2. 转换。`rrd-convert convert run.db3 -o run.rrd`
3. 打开。`rerun run.rrd`。默认可见图像、点云和 TF。
4. 扩展。按文档注册 Format Adapter、Decoder 或 Sink 后，仍用这一条命令。

一次命令选择一个 sink。v1 的 sink 是 Rerun 的 save 模式。

## 架构

```text
多种输入存储
  → Format Adapter
  → 输入中间表示       话题、类型、时间、序列化、原始字节
  → Decoder            按消息类型注册
  → 可视化中间表示     图像、点云、坐标变换、标记
  → Sink               按引擎注册
  → .rrd / Foxglove / socket 流 / 自定义格式
```

- 输入中间表示是格式适配器的唯一出口。解码器不关心数据来自哪一种存储。
- 可视化中间表示是解码器的唯一出口。Sink 不看见原始字节，也不看见 ROS 类型。
- v1 只实现 ROS 2 `.db3` 适配器和 Rerun `.rrd` sink。其它适配器和 sink 只留注册接口。

接口、消息清单和实现顺序见 [architecture.md](architecture.md)。

## 扩展模型

1. 新输入格式：实现 Format Adapter，产出输入中间表示并注册。
2. 新消息：实现 Decoder，从输入中间表示产出可视化图元，按类型名注册。
3. 新可视化引擎：实现 Sink，只消费可视化图元。可以是 Rerun `.rrd`、Foxglove 格式、socket 流或自定义格式。
4. 深度业务可视化：独立插件或私有包，不进入本仓库的默认依赖。

## v1 范围

- 语言：C++17，CMake，一个可执行文件 `rrd-convert`
- 输入：标准 ROS 2 SQLite `.db3`（常见 CDR）
- 输出：`rerun` 可打开的 `.rrd`（save）
- CLI：`convert`
- 内置消息：见架构文档中的清单
- 扩展点：Format Adapter、Decoder、Sink 三套静态注册
- 样例：合成 `.db3`，不收录私有录包
- 文档：5 分钟上手 + 最小插件示例。上手文档随第一条可用转换路径一起写

`inspect`、话题过滤、时间裁剪和批处理放到 v1.1。

## 非目标

v1 明确不做：

- 覆盖全部自研或厂商私有消息
- 厂商雷达 SDK、视频转码、相机投影叠加、业务仪表
- 仿真器、回灌评测引擎、实车上的回放控制
- 替代官方 MCAP 工具链，或实时 ROS 2 bridge
- 绑定某个 ROS 2 发行版才能运行核心路径
- 同一次运行里同时写多个引擎
- 把原始 bag 字节另存成文件。以后的 Foxglove sink 写的是可视化图元，和原样拷贝字节不是同一件事

## 与现有方案怎么比

| 方案 | 关系 | rrd-convert 差异 |
|------|------|------------------|
| 官方 db3 → MCAP → rrd | 权威两步路径 | 对外一命令；免完整 ROS；文档主推最终画面 |
| rosbag2_storage_rrd | 官方实验录制插件 | 转换已经录好的包，不绑发行版的录制栈 |
| bag2rrd | 形态接近，偏 ROS 1 | 输入和可视化引擎都可替换；v1 先做 ROS 2 `.db3` 和 Rerun |

## 成功标准

| 标准 | 对应 |
|------|------|
| 新人用样例 bag，10 分钟内在 Rerun 看到可视化 | 原则 3 |
| 标准 sensor 类型无需写代码即可转换 | 开箱 |
| 新消息类型按文档注册 Decoder 后完成一轮转换，不改主循环 | 可扩展 |
| 新引擎按文档注册 Sink 后消费同一批图元，不改解码器 | 可扩展 |
| README 首页只讲一条命令，不要求先学 MCAP | 简单 |

## 已定

- 名称 `rrd-convert`，副标题 go from any bag to Rerun
- 仓库 https://github.com/Rany010/rrd-convert

- 两条中间表示，三套注册，一次命令一个 sink
- v1 的实现组合是标准 `.db3` 加 Rerun `.rrd`
